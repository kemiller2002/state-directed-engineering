# Executive Summary

An independent review of the three frozen notes and the committed v0.2
integration found the core methodology coherent and evidence-bounded. It also
found three actionable consistency gaps: repository agent instructions did not
route into SDE authority; execution flows accidentally made feature manifests
unconditional despite the anti-ceremony exception; and templates forced one
change class despite the method's site-level multi-class model. Telemetry
guidance also needed explicit reuse of existing collectors and adaptive
capability-state semantics.

Those gaps are corrected without changing method v0.2 or rewriting research.
Because package v1.1.0 is already published, the corrected distribution is
prepared as v1.1.1. Outcome claims remain experimental. Full tests, package
inspection, installed-package verification, structural review, link checks,
frozen-history checks, and ROS validation form the completion evidence.

# Current Understanding

SDE v0.2 coherently combines semantic constraint, action constraint,
structural locality, context discovery, and failure-specific verification.
Local-first discovery identifies and understands authority; mechanical-first
execution then exposes propagation obligations before broad search. A map or
manifest predicts context but is not semantic authority. Boundary crossing is
legal when explicit and evidentiary. File size and context ratios diagnose;
they do not prove conformance.

# Key Discoveries

- Root agent routing is part of deterministic navigation, but it should only
  point to the map and method, not duplicate them.
- A map-level `manifest not needed` declaration must be first-class throughout
  the workflow or the manifest exception is illusory bureaucracy.
- Work-item classification is site-level and plural in practice; templates
  must not collapse it to one label.
- Existing ROS/project/harness telemetry is the authority when available.
  Capability state, units, scope, aggregation, and completeness must survive;
  additional provider fields may be retained adaptively without post-hoc
  schema changes.
- Published package v1.1.0 is immutable; compatible corrections require v1.1.1.
